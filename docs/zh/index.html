TurboDL 是一个 Kotlin/JVM 下载引擎，把探测、分片、并发与校验拆成清楚的阶段。控制权留在宿主，引擎负责让整条路线可观察、可恢复。

    分片

    4x

  4. 04 线路活动

    并发

  5. 05 已核对

    校验

    字节一致

    返回字节先与请求的 Range 对齐，再核对合并后的大小与终态事件。

真正有运行效力的控制项

这里只列当前有效、未废弃的开关。拨动仅演示状态，不会修改真实引擎实例。

dynamicSegmentation 动态分片

收尾托管的历史开关；它与 tailAssist 同时为 true 才生效。

tailAssist 收尾托管

工作队列空后，空闲工作单元可以接管在飞分片的尾部。

adaptiveConcurrency 自适应并发

只向下收敛。普通吞吐抖动不会减少线路数。

slowStart 慢启动

从配置的初始线路数逐步升速，而不是一次打开全部连接。

warmUpConnections 连接预热

可选的预热有超时上限，不会无限拖延正式传输。

skipProbeWhenSizeKnown 已知大小则跳过探测

宿主已知大小时，跳过额外的元数据请求。

一个仓库，七个独立站点

不安装插件框架，引擎也能完整工作。可选模块增加协议与宿主集成能力；依赖方向始终不反转。

  1. turbodl-core 必需

    HTTP Range 引擎、续传、重试、队列、DNS/代理。

  2. turbo-plugin-runtime 可选

    生命周期、清理、服务、事件与扩展点。

  3. turbo-plugin-bootstrap 可选

    一次调用装配基础运行时与 HTTP 后端。

  4. turbo-plugin-hls 可选

    HLS 点播清单、分片并发与 AES-128。

  5. turbo-plugin-js 可选

    加载 JavaScript 插件的 QuickJS 加载器。

  6. turbo-plugin-parser 可选

    微博、小红书与 Pixiv 分享链接解析。

  7. turbodl-cli 独立

    基于 SDK 的可脚本化 JAR，支持 NDJSON 输出。

失败即拒绝，而不是“差不多对”

官方插件会先写明不支持的输入，避免先产出一个损坏文件。这是产品边界，不是脚注。

插件明确拒绝为什么
HLS VOD Backend
backend.hls		直播清单（没有 `EXT-X-ENDLIST`）DRM / `SAMPLE-AES`fMP4 `EXT-X-MAP`不连续标记明确拒绝：不支持的流直接失败，而不是产出一个看起来正常、其实不对的文件。
JavaScript Plugin Loader
loader.js		注册 `DownloadBackend`（字节面留在 Kotlin 一侧）发布服务（服务是 Kotlin 对象图）`require` / npm / `fetch` —— 宿主 ABI 就是全部可用面`jar:` 与远程脚本源（目前只支持本地文件 / `inline:` / `data:`）脚本负责算 URL、请求头和签名，从不经手下载数据流。这条边界正是它不会变成带宽瓶颈的原因。
Platform Link Parser
parser.platforms		登录 — 需要会话的平台返回 null，由宿主自己的账号处理接手Pixiv 动图（ugoira）：zip + 帧时长表需要图像处理Pixiv 小说需要签名的接口（抖音 / 快手 / B站）：各自的签名算法仍留在宿主侧它的结果类型不含任何路径：`DownloadRequest` 需要 `destination: File`，而解析发生在宿主决定目录之前。临时目录占位只在边界处补上，宿主仍然走自己的路径策略。

第一次下载之前

必须用 Android 吗？

不必。核心是纯 Kotlin/JVM，要求 JVM 17+。Android 只是可能的宿主之一。

必须安装插件框架吗？

不必。turbodl-core 不依赖插件框架。可选模块只增加能力。

坐标已经上 Maven Central 了吗？

还没有。当前支持的用法是 v0.5.0.0 附件里的离线 Maven 包。

服务端忽略 Range 会怎样？

返回字节会与请求的 Range 核对。不支持或撒谎的服务端不能悄悄把字节写到错误偏移。

能下载 HLS 吗？

点播 HLS 由官方 HLS 插件提供。直播清单、DRM、fMP4 与不连续序列会被明确拒绝。

图形界面在哪里？

这个仓库提供引擎、插件框架与命令行。它有意不把界面强加给宿主。

从核心坐标开始

最小可用依赖

加入核心依赖、提交请求，并由宿主掌握生命周期。当前官方分发方式是离线 Maven 包。

implementation("dev.turbodl:turbodl-core:0.5.0.0")
