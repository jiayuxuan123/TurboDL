Gradle 依赖

把该 Release 自带的 POM 装进本地 Maven 一次，之后按坐标依赖即可 —— 下面的离线包就是这些文件：

shell
# 1) unpack the offline bundle into ~/.m2/repository
#    (or: unzip TurboDL-v0.2.4.0-mavenLocal.zip -d "$HOME/.m2/repository")
#
# 2) depend on it by coordinate / 按坐标依赖:
#    implementation("dev.turbodl:turbodl-core:0.2.4.0")
build.gradle.kts
dependencies {
    // required / 必需
    implementation("dev.turbodl:turbodl-core:0.2.4.0")

    // optional plugins / 可选插件
    implementation("dev.turbodl:turbo-plugin-runtime:0.2.4.0")
    implementation("dev.turbodl:turbo-plugin-bootstrap:0.2.4.0")
    implementation("dev.turbodl:turbo-plugin-hls:0.2.4.0")
    implementation("dev.turbodl:turbo-plugin-js:0.2.4.0")
    implementation("dev.turbodl:turbo-plugin-parser:0.2.4.0")
}
这些坐标还没有发布到 Maven Central。官方支持的用法是 Release 页上的离线包 —— 它就是 Gradle 发布到本地仓库的那一组文件。

离线包会装到哪

~/.m2/repository/dev/turbodl/turbodl-core/0.2.4.0<version>/turbodl-core-<version>.jar + .pom
~/.m2/repository/dev/turbodl/turbo-plugin-*/0.2.4.0one directory per plugin artifact
build.gradle.ktsimplementation("dev.turbodl:turbodl-core:0.2.4.0")

离线包就是一棵普通的仓库目录树：解到 ~/.m2/repository，Gradle 就能离线解析。

命令行

Release 里附带一个自包含的 CLI JAR，只要有 Java 17+ 就能跑 —— 不需要 Gradle，也不需要源码：

shell
java -jar turbodl-cli-0.2.4.0-all.jar <url> -o out.bin -c 64
java -jar turbodl-cli-0.2.4.0-all.jar <url> --json        # NDJSON, script/agent friendly
java -jar turbodl-cli-0.2.4.0-all.jar --batch tasks.txt   # one URL per line / 每行一个 URL

退出码：0 成功 · 1 下载失败 · 2 用法错误。

值得记住的几个开关

-c, --connections1..256 · default 16
-l, --limitbytes per second, 0 = unlimited
-r, --retry0..50 per segment
-b, --batchone URL per line
--jsonNDJSON: start / timing / progress / completed / summary
--doh, --proxyDNS over HTTPS, or Direct / System / Manual / PAC
--no-tail-assist, --no-overlapturn the two endgame switches off

每个开关都对应 TurboConfig 里的一个字段 —— CLI 只是 SDK 的一层薄壳。
