从这三页开始

全部通过三样东西完成：一个依赖、一个配置对象、一次提交。暂停、继续、取消、批量与诊断都在同一个 client 上。

Kotlin
// build.gradle.kts
dependencies {
    implementation("dev.turbodl:turbodl-core:0.2.4.0")
}

// Kotlin
val client = TurboClient(TurboConfig(maxConnectionsPerTask = 16))
val id = client.submit(DownloadRequest(url, File("out.bin")))
val result = client.await(id)
shell
java -jar turbodl-cli-0.2.4.0-all.jar <url> -o out.bin -c 64
java -jar turbodl-cli-0.2.4.0-all.jar <url> --json       # NDJSON
java -jar turbodl-cli-0.2.4.0-all.jar --batch tasks.txt  # one URL per line

全部配置面

九个字段，全部公开、全部有明确取值域。运行时没有别的可调项 —— 引擎没有隐藏旋钮，也没有打电话回家的默认值。

TurboConfig 的字段

maxConnectionsPerTask16 · 1..256
maxConcurrentTasks3 · 1..64
globalSpeedLimitBytesPerSec0 = unlimited
maxRetries5 · 0..50, per segment
dynamicSegmentationtrue
tailAssist / tailAssistMinBytestrue · 2 MiB
overlapMerge / bufferedSegmentWritefalse · false
minSegmentSize / blockSize64 KiB · 16 MiB
proxy / dns / trustAllCertsDirect · System · Manual · PAC / System · StaticHosts · DoH

取值是 TurboConfig.kt 里的默认值；每一个都能按 client 单独设置。

架构

这个项目的每个设计问题都由三条规则决定：

  1. core 能独立工作。turbodl-core 是完整引擎、零插件依赖；插件是纯粹的增量。
  2. 内核只是机制。它不认识任何协议 —— 只有生命周期、清理、事件总线、服务注册表、扩展点、版本握手、诊断。
  3. 依赖方向是硬的。runtime → core，绝不反向。
