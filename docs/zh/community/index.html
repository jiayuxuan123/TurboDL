问题反馈

一份能复现的报告胜过十条意见。有用的报告会写清：TurboDL 版本（v0.2.4.0）、JDK 版本、目标链接或最小复现，以及你期望的结果。

提交 issue↗

提 PR 之前要过的几关

下面就是维护者自己走的步骤。没有隐藏关卡，也没有额外要求。

检查清单

./gradlew test258 个用例，0 跳过，0 失败
dependency directionruntime → core（绝不反向）
plugin manifestturbodl-plugin.schema.json
docs官网每一页 = 仓库里的一个文件

这套测试覆盖字节级正确性、续传与插件生命周期；跑不过的改动就是还没准备好的改动。

讨论

本仓库没有开启 GitHub Discussions，所以本站也不假装有 —— 提问同样走 Issues。

一份有用的报告包含什么

四个字段；少任何一个，通常就要多来回问三轮。

模板

versionv0.2.4.0
JDKjava -version 的输出
target目标链接，或最小复现
expected / actual你期望的结果是什么

不需要别的，也不会自动收集任何信息。

参与贡献

修 bug、写新的插件后端、纠正文档都欢迎。请守住依赖方向（runtime → core），并在提 PR 前跑一遍 ./gradlew test —— 这套测试覆盖字节级正确性、续传与插件生命周期。

开源协议

MIT 协议，并附「插件生态」附加条款：插件是独立作品，可以自带任何协议；通过公开 API 交互不会让它变成 TurboDL 的衍生物。

开源协议（MIT）↗第三方组件↗使用条款↗

MIT 允许你做什么

use commercially可以
modify可以
distribute可以
sublicense可以
must keep the copyright notice需要保留版权声明
plugins独立作品，可自带任何协议

项目自身的代码是 MIT；插件生态条款只说明一件事：通过公开 API 交互不会让插件变成衍生物。
