Start here

The whole thing is one dependency, one config object, one submit call. Pause, resume, cancel, batch and diagnostics are on the same client.

Kotlin
// build.gradle.kts
dependencies {
    implementation("dev.turbodl:turbodl-core:0.2.4.0")
}

// Kotlin
val client = TurboClient(TurboConfig(maxConnectionsPerTask = 16))
val id = client.submit(DownloadRequest(url, File("out.bin")))
val result = client.await(id)
shell
java -jar turbodl-cli-0.2.4.0-all.jar <url> -o out.bin -c 64
java -jar turbodl-cli-0.2.4.0-all.jar <url> --json       # NDJSON
java -jar turbodl-cli-0.2.4.0-all.jar --batch tasks.txt  # one URL per line

The whole config surface

Nine fields, all public, all with a documented range. Nothing else is tunable at run time — the engine has no hidden knobs and no phone-home defaults.

TurboConfig

maxConnectionsPerTask16 · 1..256
maxConcurrentTasks3 · 1..64
globalSpeedLimitBytesPerSec0 = unlimited
maxRetries5 · 0..50, per segment
dynamicSegmentationtrue
tailAssist / tailAssistMinBytestrue · 2 MiB
overlapMerge / bufferedSegmentWritefalse · false
minSegmentSize / blockSize64 KiB · 16 MiB
proxy / dns / trustAllCertsDirect · System · Manual · PAC / System · StaticHosts · DoH

Values are the defaults in TurboConfig.kt; every one of them can be set per client.

What a plugin manifest looks like

A plugin is a JAR plus this file. The reference page lists every field, its type, whether it is required, and the allowed values.

turbodl-plugin.json

{
  "manifestVersion": "1.0",
  "id": "parser.example",
  "name": "Example parser",
  "description": "Turns example:// links into download requests.",
  "version": "0.1.0",
  "author": "you",
  "homepage": "https://github.com/you/turbodl-plugin-example",
  "license": "MIT",
  "category": "turbodl-parser",
  "capabilities": [
    "dev.turbodl.cap.parser"
  ],
  "protocols": [
    "example"
  ],
  "turbodl": {
    "apiMajor": 1,
    "requiredApiVersion": "1.0.0"
  },
  "entry": {
    "language": "kotlin",
    "pluginClass": "com.example.ExamplePlugin"
  },
  "extensionPoints": [
    "turbo.linkParser"
  ]
}

Architecture

Three rules decide every design question in this project:

  1. core works alone. turbodl-core is a complete engine with zero plugin dependency; plugins are strictly additive.
  2. the kernel is only mechanism. It knows no protocol — lifecycle, cleanup, event bus, service registry, extension points, version handshake, diagnostics.
  3. dependency direction is strict. runtime → core, never the reverse.
