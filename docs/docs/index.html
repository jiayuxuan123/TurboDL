Start here

The whole thing is one dependency, one config object, one submit call. Pause, resume, cancel, batch and diagnostics are on the same client.

Kotlin
// build.gradle.kts
dependencies {
    implementation("dev.turbodl:turbodl-core:0.2.0.9")
}

// Kotlin
val client = TurboClient(TurboConfig(maxConnectionsPerTask = 16))
val id = client.submit(DownloadRequest(url, File("out.bin")))
val result = client.await(id)
shell
java -jar turbodl-cli-0.2.0.9-all.jar <url> -o out.bin -c 64
java -jar turbodl-cli-0.2.0.9-all.jar <url> --json       # NDJSON
java -jar turbodl-cli-0.2.0.9-all.jar --batch tasks.txt  # one URL per line

Architecture

Three rules decide every design question in this project:

  1. core works alone. turbodl-core is a complete engine with zero plugin dependency; plugins are strictly additive.
  2. the kernel is only mechanism. It knows no protocol — lifecycle, cleanup, event bus, service registry, extension points, version handshake, diagnostics.
  3. dependency direction is strict. runtime → core, never the reverse.
