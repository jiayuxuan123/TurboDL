# TurboDL 0.5.0.3

版本：`0.5.0.3`（相对 `0.5.0.2`）

本版增加任务级传输策略和执行诊断，完善同源任务之间的限流协作、自动重试退出及来源失效处理。新能力通过附加接口提供，原有请求与事件契约保持兼容。

## 任务策略

- 新增 `TaskTransferPolicy` 和 `submitWithPolicy(...)`。调用方可为单个任务覆盖分片大小、块大小、每连接分片数、慢启动、自适应并发模式、按主机连接上限和背压分组；未设置项继续沿用 `TurboConfig`。
- 提交任务时冻结分片、慢启动等任务级参数。全局限速与总连接预算继续统一生效。
- 未使用新入口的调用继续沿用原有提交路径和默认行为。
- 原有背压参数设为 `0` 时仍表示关闭；新增分组能力不会自动开启背压。

## 调度协作

- 同一来源、同一背压分组内的任务共享来源限流冷却和恢复判定。某个任务收到 429/503 后，组内任务按同一冷却状态等待；恢复时逐步放开并发。
- 不同来源或不同分组的任务不共享冷却，避免一个来源的限制影响其他任务。
- 来源等待时间过长时，只从当前任务中移除，其他任务仍可按原策略使用该来源。
- 来源返回内容与目标文件不符并被移除后，迟到的成功响应不能将其重新恢复到当前任务。

## 重试与断点

- 服务端返回的 `Retry-After` 超过允许等待上限时，自动重试停止，已有断点保留，可按续传流程继续。
- 自动重试停止时不清空已写入的数据，后续继续下载沿用已有断点。

## 任务详情

- 新增 `TaskTransferDetails`，可查看任务阶段、配置连接数、当前和峰值活动 HTTP 请求数、请求次数、接收字节、首字节时间、探测/传输/收尾耗时、最近 HTTP 状态和失败阶段。
- 当前并发按活动 HTTP 请求统计，不把配置连接数当作实际值；请求指标不可用时明确标记。
- HTTP 错误可在任务详情中定位到状态码和失败阶段，便于区分请求、传输和收尾问题。

## 验证范围

- 在来源最多允许 2 条传输、双任务同时下载的本地受控测试中，9 组交错对照的中位耗时由 2.38 秒降至 1.45 秒；全部文件校验一致。该结果只代表该限流模型。
- 真实夸克文件完成 3 轮稳定版、候选版与参考实现的对照，9 次下载均通过官方 SHA-256 校验。候选版默认吞吐与稳定版接近，未据此宣称公网普遍提速或全面超过参考实现。
