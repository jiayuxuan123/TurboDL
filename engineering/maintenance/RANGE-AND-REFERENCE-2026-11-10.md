# 首响应启动、尾段接管与文析内核对照

本记录属于 0.5.0.1 之后的常规维护批次。未改发布版本、SDK 公共接口、默认连接上限或宿主的自适应策略。与[同批 HLS 和连接池维护](BATCH-2026-11-09.md)一起评估，避免把单个小修改单独发版。

## 已复现并修正

### 首个响应体阻挡其他连接

`SegmentDownloader.downloadSegmentInto` 已经在响应头到达时学到终址，但单飞门直到整个首段完成才打开。首段慢时，其余 worker 等满 300 ms；终址相同、不需要重定向的普通 Range 也支付这项等待。

现在在过滤 HTML 错误页后立即打开门，保留异常退出的 finally 释放和任务取消检查。门仍按任务和原始来源隔离，跨源凭据清理和 300 ms 异常兜底保持原语义。

回归让第一段在真实 HTTP 响应、实际写入后暂停，然后使用协程虚拟时钟检查第二段能否在不推进超时时完成。修复前此断言失败，修复后通过；它不依赖机器在某个墙钟时限内完成。

### 小尾段阈值没有真正生效

`tailAssistMinBytes` 默认为 8 KiB，但切分仍一律向下按 64 KiB 对齐。半段不足 64 KiB 时结果为 0，所以空闲 worker 无法接走本来已超过阈值的 16..128 KiB 剩余区间。

现在大区间继续保持 64 KiB 粒度，仅在半段不足 64 KiB 时使用更小的有效粒度。切点仍在原分片写锁下修改，遵守最小尺寸与最大拆分次数。阈值判断使用除法避免乘 2 溢出。

回归包含 48 KiB 非周期文件、两条初始 Range、一个慢分片，要求出现实际接管请求并验证完整 SHA-256。修复前仅两次请求、断言失败；修复后接管并产出正确字节。另验证 `Long.MAX_VALUE` 最小阈值安全禁止拆分。

## 测量台与边界

- `download_profiles.mjs` 提供纯本地的固定非周期内容：32 MiB 不限速、16 MiB 每连接 200 KiB/s、1 MiB 延迟响应、48 KiB 慢尾段。
- `compare_ranges.py` 每侧先预热，AB/BA 交错至少 5 组；CV 超过 15% 扩展到最多 9 组。保留 p50、p95、配对 bootstrap 区间和全部失败日志。
- Range 产物逐轮独立计算预期 SHA-256，不用文件长度代替校验。每轮结束删除自己创建的下载目录，不累积测试载荷。
- 测速写盘使用相同 SSD 目录。体积较大的原始证据、对照程序和冻结 JAR 放在 `D:\CodexResearch\turbodl-maintenance-20261110`。
- `engine_ms` 是任务进入到完成的时间；`wall_ms` 另列 JVM／进程启动和退出。Wenxi 包含自身探测和 20 ms 状态轮询。整个子进程 CPU／RSS 包含初始化、JIT 和后台线程，不能冒充稳定态传输或 Android 数据。
- 延迟与尾段专测使用每连接一个初始分片；普通下载使用 SDK 默认每连接 4 片。自适应保持开启、显式慢启动关闭、连接预热关闭。没有使用账号或私有网盘链接。

## 文析原始内核

参考源码固定到 `z7786/wenxi@28e7b4576f5c3a600a44240967c03e21ef579a1f`，直接构建其 `native/gopeed/cmd/asterlink`。没有修改该内核，也没有复制其实现到 TurboDL。

构建使用 Go 1.25.7、`GOTOOLCHAIN=local`、`CGO_ENABLED=0`、`-mod=vendor`、`-p 4` 和 `-trimpath`；产物、构建日志、源码归档留在 `D:\CodexResearch\wenxi-28e7b457-20261110`。通过原有 stdin/stdout 协议调用 open、begin、snapshot、close，输出文件按照该项目的宿主契约预先创建。

源码确认：普通来源与夸克来源采用不同最小分片粒度；部分来源单独限制并发；过载冷却按主机协调。这些是宿主／来源策略的参考，不把网盘账号逻辑塞入通用 SDK。云取 aria2 已发现的 16 连接截断、恢复身份和统计修复见[应用侧记录](../../../YunGet/engineering/aria2-and-reference-review-2026-11-10.md)。

同源比较已确认双方完成真实传输并逐次通过独立 SHA-256。初轮中，TurboDL 在每连接限速场景仍慢于文析；不限速样本波动较大，不能作稳定倍数结论。文析演示中的 122 MB/s 不属于同环境数据，本轮结果不能外推为手机网盘速度。
