# TurboDL 0.5.0.5 验证摘要

本版修复失败归因，不包含调度或吞吐算法重写。

## 受控验证

- 探测成功后，分片持续返回 `503`：最终错误文本包含具体的 `HTTP 503`，任务详情保留 `lastHttpStatus=503`。
- 同一场景的失败阶段为 `TRANSFERRING`，不再因为尚未收到首字节而误判为 `PROBING`。
- 真实探测 `429/503`、长冷却、暂停取消、连接预算释放、弱校验器取消和断点保留测试继续通过。
- 应用侧保留不完整请求指标中的 HTTP 状态和失败阶段，不再整条丢弃。

## 结论边界

- 这是正确性和可观测性修复，不宣称提高本次测试中的下载吞吐。
- 旧客户端已上传的历史事件不能被追溯改写；新版失败事件才会携带精确状态。
