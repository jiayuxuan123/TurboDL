# TurboDL 0.5.0.2

本版为常规维护更新，保留 Kotlin/JVM SDK、插件和现有可选原生入口。

## 优化

- HTTP 初始分片软下限调整为 256 KiB，减少小范围请求的启动开销；小文件仍按文件大小和连接上限裁剪。显式 64 KiB 等设置继续支持，续传继续沿用原网格。
- 首个分片拿到响应头后即可放行其他分片，不再等待整个首段下载结束。
- 根据真实传输窗口、请求启动成本和空闲连接速度分配慢尾段。等待首字节、已接近完成或无法获益的请求不会盲目拆分；多镜像不套用另一来源的速度估计。
- 最后一个请求结束后唤醒等待中的 worker，减少收尾轮询等待。
- 断点快照使用有界缓冲输出，保留 v2 格式、先同步数据后同步侧车的顺序和原子替换。周期快照移出数据读取回调，每个任务最多一个待处理周期快照；暂停和终态仍强制落盘。
- 显式空闲连接上限不再被任务连接数抬高，活动请求能力保持独立。
- HLS AES-128 改为流式解密，顺序 worker 复用缓冲；轮换密钥使用有界并行预取，取消时及时关闭请求并清理未完成文件。

## 修复

- 修复尚未完成测速的慢镜像持续取得额外请求、妨碍快镜像承担流量的问题。
- 所有镜像退避时的备用选择继续遵守每来源连接上限。
- 修复同步快照落盘阻塞数据读取、可能被误判为慢尾段而产生重复范围请求的问题。

## 兼容性与验证

- 公共构造器、请求模型、插件 ABI 和已有 CLI 参数保留。`minSegmentSize` 的默认值变化已明确列出；手动设置和已保存断点不会被改写。
- Android 继续使用 Kotlin/ART 路径。原生启动器版本同步更新，原生数据面算法未在本版重写。
- 开发阶段的受控 A/B、构件摘要与限制见同目录对标记录和发布附件 `AB-REPORT`。高波动结果保留为未定，不用于宣称所有网络或所有场景全面超过其他下载器。
- 最终自动化结果和平台边界分别随包提供 `TEST_REPORT.json` 与 `PLATFORM-MATRIX`；编译验证与实际运行验证分别记录。
