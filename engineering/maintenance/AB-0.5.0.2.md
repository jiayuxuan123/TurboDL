# TurboDL 0.5.0.2 测量记录

## 范围与方法

本批使用 Windows、JDK 21.0.12 和同一磁盘上的受控 HTTP 来源。常驻 SDK 与冷启动 CLI 分开记录，预热次数相同、执行顺序交错。常规对照至少 5 组，变异系数超过 15% 时最多扩展到 9 组；达到上限后仍高波动的结果保留为未定。每个下载样本独立核对预期 SHA-256，文件在校验后清理。

下表用于隔离单项改动，构件摘要和配置保存在各实验 manifest 中。开发阶段快照不等同于所有最终使用环境的固定收益，不能据此承诺所有网盘达到演示视频的速度。

## 初始分片

保持每连接目标 4 片，仅比较 64 KiB 和 256 KiB 软下限。软下限仍按文件大小和连接上限裁剪，不强制削减小文件的连接机会。

| 场景 | 64 KiB p50 | 256 KiB p50 | 请求数前→后 |
| --- | ---: | ---: | ---: |
| 32 MiB、不限速、16 路 | 211.17 ms | 219.96 ms | 64→64 |
| 16 MiB、每连接限速、64 路 | 1443.64 ms | 1387.81 ms | 256→64 |
| 1 MiB、高延迟、8 路 | 591.57 ms | 336.71 ms | 16→8 |
| 48 KiB、慢首段、2 路 | 425.54 ms | 423.82 ms | 3→3 |
| 16 MiB、一个慢连接、8 路 | 342.73 ms | 330.07 ms | 33→33 |

高延迟模型约 1.76 倍；其他场景的中位变化在 5% 内，不能将这些小差异统一称为显著提速。原始实验：`warm-initial-minimum-ab-01`。

直接改成每连接初始 1 片的候选曾使慢连接模型退化约 2.27 倍，未采用。保留多片目标和已验证的运行时尾段分配。

## 慢尾段与收尾

按请求成本和实际速率分配尾段的首个独立对照中，16 MiB 单慢连接模型从 579.46 ms 降至 339.20 ms，约 1.71 倍。其余四场景的中位退化均在 5% 内，全部内容摘要正确。后续加入慢 helper 和跨镜像速率误用保护，保持保守回退。

收尾通知与缓冲快照的组合对照中，每连接限速模型为 1399.30→1374.34 ms，高延迟为 335.43→321.26 ms，单慢连接为 349.97→319.35 ms。不限速及小慢尾部分结果波动较高，不作为固定提速倍率。原始实验：`warm-checkpoint-drain-ab-01`。

## 断点快照与恢复

64/256/1024 片的快照交错测量，中位写入耗时分别为 8.19→5.31 ms、9.71→5.51 ms、19.57→6.73 ms；部分变异系数超过 15%，不宣传为稳定倍数。所有样本验证 v2 字节格式和目标文件 SHA-256。

最终回归发现同步快照会阻塞读取、诱发额外尾段请求；改为最多一个后台周期快照，强制落盘仍保留。强校验续传用例实际重新传输 1,966,081 字节，恰好是 2 MiB 减去已保存的 128 KiB，再加 1 字节探测，原严格断言通过。

## HLS 与镜像

- 轮换 8 个密钥、单请求延迟 50 ms 的受控模型为 613.94→165.61 ms，约 3.71 倍；32 MiB AES 分片的分配量约 168.76→68.23 MB。分配量不等同于峰值 RSS，普通小分片的耗时结论仍未定。详见 `BATCH-2026-11-09.md`。
- 镜像冷启动修复前，快慢来源各承担约 2 MiB；修复后快来源写出约 3.5 MiB、慢来源约 1 MiB。该计数包括尾段接管产生的额外写出，不作为端到端提速倍率。

## 文析参考与未验证项

参考固定为 `wenxi@28e7b4576f5c3a600a44240967c03e21ef579a1f` 的原始 Go helper，未导入其实现到 SDK。

开发快照的 256 MiB 对照，中位耗时约 1603.61 ms 与 1609.47 ms；SDK 变异系数约 20.6%，95% 区间较宽，**结论未定，不能宣称已全面超越**。较小文件仍有准备、持久化和收尾开销差距。该组用于定位，不用于虚构最终版的全场景排名。

没有执行同账号、同文件、同网络的真实网盘比较，也没有本轮手机连接证据。原生数据面算法未在本版重写；`native/README.md` 中的旧原生 A/B 已明确标注为 0.5.0.1 历史记录。

最终发布回归以随包 `TEST_REPORT.json` 为准；诊断测量台没有实际传输时，不作为性能证据。
