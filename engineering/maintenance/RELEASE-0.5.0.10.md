# TurboDL 0.5.0.10

- 原生下载进入尾段时，空闲连接可按预计完成时间分担剩余 Range。引擎会衡量新请求的启动成本和预期收益，也会记录拆分边界，供暂停后继续下载。
- 同一批并发请求返回 HTTP 429 或 503 时，合并计算重试次数，只降低报错来源的并发。连续限流会延长退避。服务端要求较长等待时，保留断点并停止本轮重试。
- Kotlin/JVM 吞吐自适应以整个采样窗口的活动连接峰值判断样本是否有效。降档前启动的请求不会抬高低档评分。反复被拒的档位会延后重测。
- 分发更新后的 Kotlin/JVM SDK、Windows x64 原生引擎和四种 Android ABI 原生库。Android 库通过 16 KiB ELF 对齐检查。

Windows 全量原生门禁 106 项通过，Kotlin/JVM 测试通过。8 MiB 限速夹具用四条连接交替测试两版各三次，完成时间中位数从 6.33 秒降至 5.62 秒，六份文件的 SHA-256 一致。网盘上的实际表现受账号、来源策略和网络影响。
