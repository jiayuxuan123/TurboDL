# TurboDL 0.5.0.4

版本：`0.5.0.4`（相对 `0.5.0.3`）

本版集中修复探测阶段的限流处理和取消行为。已有下载接口、任务策略、断点格式和插件 ABI 保持兼容。

## 修正内容

- 探测请求收到 `429` 或 `503` 时先读取 `Retry-After`，再决定是否重试，不再把服务器的限流页误判为用户代理拦截。
- 服务端要求等待较长时间时停止本轮自动重试，保留已有断点并报告限流原因，不再用连续请求绕过等待。
- `Retry-After` 的秒数和 HTTP 日期形式都可识别；过大的提示值只用于诊断，不会让后台任务无限等待。
- 暂停、取消或作用域结束时，正在阻塞的探测请求和弱校验器指纹请求会及时关闭，立即释放全局连接名额。
- 取消等待的任务不会阻塞后续任务；已完成且可复用的正常请求不会被错误取消。

## 验证

- 新增5项真实 HTTP 稳定性测试，覆盖限流等待、长冷却、探测取消、指纹取消和连接预算释放。
- 相关7个测试套件、39项测试通过，包含断点保留、连接复用、源冷却和 SHA-256 结果校验。
- 发布门禁覆盖 core、CLI 和全部插件模块：116 个测试套件、634 项测试、0 失败、0 跳过。

## 兼容性

- Maven 坐标和公开 API 不变。
- 旧断点、旧任务和现有插件无需迁移。
- Windows、Linux、macOS 原生启动器同步更新版本号；Android 继续使用 Kotlin/ART 路径。
