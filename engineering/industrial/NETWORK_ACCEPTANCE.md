# 网络、断点和竞品验收协议

版本：计划 v1，2026-11-04。本文规定后续如何做实验，本轮未执行以下新实验。
与 [ROADMAP.md](ROADMAP.md) 配合使用；所有来源、机器和竞品版本在 P00 冻结。

**强制预算门禁：**本轮所有公网实验（候选、旧版、竞品、重试、镜像、断点和失败重跑）
累计不得超过 **8 GiB = 8192 MiB**。预算分配、预留、回填和超支中止规则见
[EXECUTION_BOARD.md](EXECUTION_BOARD.md) 第 3 节；没有持久账本或无法核对流量时，
公网 cell 只能是连通性检查或 `BLOCKED`，不能计作 PASS。

## 1. 比较对象和能力边界

| 对象 | 角色 | 执行要求 |
| --- | --- | --- |
| curl 单连接 | 普通下载基线 | 禁用并行、不额外限速；新传输与断点恢复分别测 |
| TurboDL 已发布 0.4.1.0 | 回归基线 | 保存原始 JAR 哈希；不能用新编译 JAR 冒充旧版 |
| TurboDL 当前候选 | 被测对象 | 记录提交、构建依赖和 JAR 哈希；最终验收使用同一候选 |
| aria2 | HTTP/恢复/多来源/协议主对标 | 固定实际二进制、构建特性；先记录支持的最大连接数 |
| Gopeed headless | HTTP/BT/扩展接入对标 | 固定服务/配置；通过 API 自动收集结果；关闭无关 GUI 开销 |
| XDM | HTTP 调度/断点/媒体对标 | 能自动化则适配；GUI 手工结果要标方法和重现限制，不能凭印象打分 |
| axel / AB Download Manager | 补充专项 | 只在有明确能力差距时加入，避免重复下载占预算 |

竞品官方材料：

- [aria2 手册](https://aria2.github.io/manual/en/html/aria2c.html)：HTTP(S)、FTP/SFTP、BT、Metalink、校验与会话能力。
- [Gopeed 官方仓库](https://github.com/GopeedLab/gopeed)：当前功能、版本与 API 入口以该版本文档为准。
- [XDM 官方仓库](https://github.com/subhra74/xdm)：调度与媒体边界以冻结版本实际行为为准。

这些来源用于确定要测什么，不用其宣传速度充当结果。参考实现只定向读与失败有关的入口；
若复用第三方源码/库，先核对许可证，不能把 GPL 源码复制进 MIT core 后声称只是借鉴。
本机已有参考材料在工作区 `_research/turbodl-upstreams/`；先核对版本，避免重复整仓下载。

同条件比较有两条轨道，必须同时保留：

1. 共同档位：例如 aria2 原构建只允许某个最大值，就在共同支持的档位比较，不擅自改竞品上限。
2. 用户生产配置：各引擎使用合理配置和各自支持的上限，记录实际连接/内存/失败率，不能冒充共同档位实验。

协议 N/A 表示竞品本来不支持，不算被 TurboDL 击败；TurboDL 的规划协议缺口仍是 TODO/BLOCKED。

## 2. 实验记录与正确性前置

每次 run 至少保存以下字段（原始结果 JSONL，汇总 CSV/Markdown）：

```text
run_id, case_id, attempt, timestamp, baseline_commit, candidate_commit
engine_name, engine_version, binary_sha256, runtime, os, device, filesystem
source_id, origin_group, object_size, expected_sha256, etag_kind
network_path(direct/proxy), proxy_kind, protocol_negotiated, cache_state
requested_connections, desired_connections, in_flight_requests, sockets, h2_streams
task_count, per_host_limit, global_limit, adaptive_mode, slow_start, tail_assist
time_process_start, time_submit, time_first_payload, time_last_payload, time_verified, time_terminal
useful_bytes, wire_bytes, retry_bytes, retries_by_reason, terminal_state, actual_sha256
budget_bytes, budget_remaining, budget_stop_reason
cpu_seconds, peak_rss, managed_heap, direct_memory, peak_threads, handles, open_sockets
resume_persisted_bytes, resume_reused_bytes, refetched_intervals, failure_injection
exit_code, completed_event_present, eligibility, exclusion_reason, evidence_paths
```

- URL、查询签名、请求头、用户名和 Cookie 不写公开结果；source_id 指向本机私有配置。
  私有配置不能提交。对外只保留来源类别、可公开 URL、无秘密复现脚本和摘要。
- 以独立生成/发布的预期 SHA-256 为准；只算本地摘要但没有预期值，只能证明文件可读，不能证明正确。
- 错位语料必须非周期：种子 + 块序号生成不同字节；服务器端先存独立摘要。不能沿用重复 64KB 填充证明偏移正确。
- exit=0、文件长度正确、存在 completed、全摘要正确、无未处理后台错误，五项都满足才能计速度。
- 正确但极慢的结果也保留；错误结果列失败，不能当作“异常值”删掉。只有外部证据明确的环境异常才排除。
- 不把 JUnit 中主动 return 的基准当执行：结果必须包含实际传输字节和网络 run_id。
- CI 生成报告的空套件、缺失 XML、零传输也直接阻止宣称网络验收完成。

## 3. 时间、速度和资源的统一口径

同时报告端到端完成时间（含进程/SDK 起步、探测、传输、最终校验）和纯载荷传输时间。
JVM 冷启动与复用 SDK 各一组；不能只给对 TurboDL 有利的热 JVM，却让竞品冷进程起跑。
各引擎校验工作不同，端到端一律增加独立全摘要核对，另报引擎内置校验成本，避免 CLI 多读一次文件干扰归因。

goodput = 最终有用字节 / 明确定义的时间段；重试/探测/预热/重复下载不计入有用字节。
用 MiB/s 表示二进制速率，MB/s 表示十进制，报告不混用。百分比/ETA 未知值保持未知。
连接数以服务器日志/客户端网络事件/OS socket 为证，分别列出；progress 中的字段不自动等同实际 socket。

资源报告同时给空闲基线、活动增量、总峰值与工作完成后的回落。不能从 JVM RSS 中减掉任意数后
与原生进程总 RSS 比较；不能要求线程池所有线程退出才算无泄漏，保留池要有上限并回到声明的稳态。

## 4. 本地受控矩阵：先分离原因

基础语料：1 MiB、32 MiB、256 MiB、2 GiB；零字节/超 4 GiB 属于正确性专项，生成时按空间预算顺序执行。
连接档位：1/4/8/16/32/64/128/256；并行任务：1/4/8/32。不是把所有维度全排列：
单因素先跑完整档位，组合采用成对覆盖，下面列出的高风险组合必须单独执行。

| ID | 服务端模型 | 必须观察 |
| --- | --- | --- |
| L01 | 无人为限速 Range | 高并发线程/请求/切片税，吞吐和 CPU 不出现无法解释的断崖 |
| L02 | 每连接独立限速 | 增加连接能换吞吐，降档不能用尚未退出的旧请求伪造收益 |
| L03 | 全局总量限速 | 不错误承诺线性提速；自适应减少无用连接且保留吞吐 |
| L04 | 延迟/抖动/少量断连 | 合理重试、连接复用和收尾；不因单条慢连接拖住全文件 |
| L05 | 并发上限与 429/503 | 尊重 Retry-After、有界退避和恢复，不持续撞墙 |
| L06 | 少数连接慢 10 倍 | ETA 分割和工作窃取是否真正改善尾部 |
| L07 | CPU/慢盘/空间不足 | 识别瓶颈，预算不失控，暂停和失败仍及时响应 |
| L08 | 无 Range/忽略 Range/坏 206 | 安全回退或明确失败，没有错位/假成功 |

必测组合：256 路 × 动态尾段 × 暂停重启；多任务 × 全局限速 × 代理热切换；
UPWARD/DOWNWARD × slowStart × 背压恢复；镜像换源 × 内容变化 × 断点恢复。
服务器的 backlog、处理线程/事件循环、限速精度和 CPU 必须先验明能支撑流量；
Python 测试服务器自身封顶时记录“测试台瓶颈”，换 Node/独立服务器交叉验证，不能怪引擎或宣布达标。

## 5. 公网矩阵：不能再只用回环证明

每种来源由 P01 先探测支持性、对象长度/摘要、Range、稳定时效；正式实验清单先登记再跑。
至少三个独立来源/网络模型，其中至少两个非同一 CDN、至少一组能体现按连接限速的授权来源。
若公网找不到可控限速来源，受控公网服务器与真实 CDN 分开计数，缺失项保持 BLOCKED。

| ID | 来源/路径 | 场景 |
| --- | --- | --- |
| N01 | GitHub Release 原始资产 | 跟随重定向、冷/暖连接、小/大文件 |
| N02 | 独立公开 HTTPS 文件源 | 不同 CDN/源站，明确对象摘要，原生 Range |
| N03 | 自有/获授权的公网测试源 | 固定对象，受控每连接/总量限速、断连和链路延迟 |
| N04 | 获授权网盘临时直链 | 宿主注入头与刷新，过期前/后恢复；资料留本地，不扫用户凭据 |
| N05 | Cloudflare 下载代理 | 缓存 MISS/HIT 分开，与原始资产分组；改善是链路贡献，不归功引擎算法 |
| N06 | 相同来源经 HTTP/SOCKS/PAC | 和直连分组；所有引擎相同代理，不把不同出口混为同条件 |
| N07 | Android 真机 Wi-Fi/移动网络 | 屏灭、换网、续传、资源占用；记录设备、运营商/网络类别 |

每来源先做 1/16/64/256 路三次小样本定位，再选择满足条件的正式对象：
32 MiB 附近文件覆盖启动；256 MiB–1 GiB 对象覆盖稳态和断点。源只允许小对象时不可冒充稳态大文件。
正式连接阶梯仍覆盖 1/4/8/16/32/64/128/256；竞品不支持的档位只作 TurboDL 自身伸缩分析。

正式每个可比较 cell 至少 5 个成对轮次，顺序交错并随机种子固定，不能所有 TurboDL 在先、竞品在后。
若变异系数 >15%，最多扩到 9 轮并分时段；仍不稳定标“结论不足”，不无限加样本挑最好值。
下载量可在清单中预计：对象大小 × 引擎数 × 档位 × 重复数；阶段性先小后大，失败先诊断再重跑。
所有预计值必须在 EXECUTION_BOARD 的 8 GiB 账本中预留，实际响应体（含重试）回填；
不能只按最终文件大小记账。用户已开放公网测试；正式执行仍要核对当轮是否有新的网络限制，
不需要为每次普通下载重新询问。

## 6. 断点/故障验收：结果正确与少重下载同时成立

所有下列 cell 在 10%/50%/95% 进度至少各触发一次；时序敏感问题用固定种子多次扰动。
记录源端实际收到的 Range 与发送字节，不能仅凭进度条认定复用了断点。

| ID | 注入 | 必须成立 |
| --- | --- | --- |
| R01 | pause/resume 同 SDK | 从耐久区间继续，已完成区间不整段重复获取 |
| R02 | shutdown 后新 SDK 同 stableKey | 正确恢复；池/文件锁释放；相同键不能双写 |
| R03 | 精确 PID 强杀并重启 | 数据和侧车一致，摘要正确；未知范围重下但不误报完成 |
| R04 | 整机重启/断电设备试验 | 明确文件系统/刷盘保证；强杀测试不能替代此项 |
| R05 | 目标删/截断/改写/重名 | 识别失效；不沿用虚假的预留长度，不覆盖用户另一文件 |
| R06 | 侧车主/备/临时文件截断或版本改变 | 恢复最后可信快照或明确提示，保留可救数据 |
| R07 | 403/签名过期/临时断网/探测超时 | 保留断点；宿主刷新通用来源后安全恢复；不是盲目从零开始 |
| R08 | 同长度换内容/弱 ETag/样本相同尾部不同 | 识别或保持不可信并按策略处理，绝不输出混合文件成功 |
| R09 | 主源/镜像变化、206/200/416 切换 | 身份与范围重验，安全回退、坏源隔离且不越源传凭据 |
| R10 | 磁盘满/权限丢失/保存失败 | 错误可归因，已下载数据可保留，用户可在有空间后继续 |

精度指标：可证明已耐久的区间不得整段重下；允许重下未承诺的检查点尾窗、协议必要探测和被中断请求。
先在配置中登记检查点时间窗和最大未提交缓冲预算，再据此计算允许重复字节，不能看完结果才放宽。
按 `重复字节 / 文件大小`、恢复首字节时间和完成时间与竞品比较。不同检查点耐久保证分别列出。

## 7. 阶段性量化门槛

以下是预登记目标，不是当前测量值。P00 可根据硬件标定补充绝对预算；修改阈值要先记录理由，
不得为失败样本临时放宽。任何数据损坏、凭据越界、无限 await 都直接 FAIL，不参与速度抵消。

| 指标 | 通过方式 |
| --- | --- |
| 功能正确性 | 必测行全部摘要一致/预期失败正确；错误文件冒充成功为零 |
| 性能不回退 | 每个强制 cell 的成对完成时间比值（参考耗时/候选耗时）中位数 >=0.95 |
| 对竞品非劣 | 共同能力选择冻结版本的最强有效参照，按同样阈值逐行判断；不只挑弱竞品 |
| 有收益场景 | 预登记 L02/N03 等具备带宽余量的主要场景，争取相对已发布版及普通单流 >=1.3x |
| 波动 | 报中位数、p95、范围和成对 bootstrap 95% CI；CI 无法支持非劣时为 VERIFYING |
| 资源 | 与自身已发布版活动增量相比 CPU/峰值 RSS 不恶化 >10%，或有审批过的实证权衡 |
| 停止 | 命令调用 p95 <=500ms；在途网络/写盘清理通常 <=2s，特殊 DNS 硬超时另报不可伪装 |
| 限速 | 稳态 30s 实际传输窗口误差 <=5%，额外说明桶突发额度及整文件短任务误差 |
| 公平 | 固定同权任务在有传输能力时无持续饥饿；优先级规则由调度契约明定 |
| 长跑 | 24h 零假成功/死锁/泄漏；同负载静置后 RSS/句柄/线程回到登记的稳态容差 |

5% 是验收的工程容差，不表示每条链路都有显著提升；主张“更快”必须提供成对置信区间和实际收益。
若出现退化，先按 DNS/探测/建连/传输/写盘/校验拆时归因，然后做一次局部改变，不能同时改所有参数。

## 8. 长跑与故障统计

先 30min 资源冒烟，再 2h 故障混跑，最后 24h soak；长跑不依赖下载同一公网大文件上千次，
大部分负载用受控服务，期间插入真实公网探针；真实链路实验与本地负载结果分开报告。
每分钟采资源，每次任务记终态，发生错误保留上下文而不把带密钥的 URL 写日志。
恢复后 30s、2min 采空闲资源；解释连接池/GC 余量的上限，检查随累计任务数持续增长的趋势。
检测失败立即停止该 cell、保留现场并退出关联服务，其他独立验证可继续；不通过无限重试刷成功率。
