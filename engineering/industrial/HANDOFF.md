# 给后续模型的执行手册

日期：2026-11-04。规划已冻结，第一轮有限执行已完成并记录在
[evidence/2026-11-04-engine-pass1.md](evidence/2026-11-04-engine-pass1.md)。
后续按执行板领取任务，不重新做全仓审计；不能把第一轮局部结果当成全范围完成。

## 1. 第一屏需要知道的事

- TurboDL 是通用 JVM SDK；YunGet 是 Android 消费者。网盘账号、解析、刷新和平台策略属于 app。
- 保留自适应，宿主决定 DOWNWARD/UPWARD、slowStart、初始值、上限和恢复策略。
- 用户要所有部分逐步兑现，不能做好一个优化就忽略断点、资源、协议、插件与兼容。
- 现有少量公网结果不是完整对标；本地 JUnit PASS 不等于真实网络/真机 PASS。
- 本轮公网实验硬上限是累计 8 GiB；先读 [EXECUTION_BOARD.md](EXECUTION_BOARD.md) 第 3 节，
  没有账本/预留/流量核对就不开公网 run。
- 开工前先查 [RISK_REGISTER.md](RISK_REGISTER.md) 中与自己任务相关的 S0/S1；静态风险不等于已复现，
  但修复时必须留下最小复现与回归。
- Windows 客户端暂停。YunGet 后续 UI 是基于现有 Material 3 适度升级，功能和观感不能回退。
- 已发布 TurboDL 0.4.1.0、YunGet 2.7.23；修改进入下个版本，不能覆盖旧附件。
- 公网账本唯一默认目录为 `_bench/results/traffic-budget/`；不要新建空账本重置 8 GiB。
- 只动当前任务负责的文件；不要碰 `hub/`、`accounts/`、`ccswitch/` 或既有桌面工作。

## 2. 最小阅读量和成本规则

1. 先读 [ROADMAP.md](ROADMAP.md) 第 1–4 节、
   [EXECUTION_BOARD.md](EXECUTION_BOARD.md) 的批次/预算规则和自己领取的任务卡，检查状态/HEAD。
2. 只读卡片列出的生产入口和相关测试。参数变更再读 API_CONTRACTS 对应分组，
   做基准才读 NETWORK_ACCEPTANCE 对应部分。不要重新打印全部 README/全部配置/所有日志。
3. 最多 5 个定向文件/符号搜索后应形成一个可复现假设；仍找不到再扩大到调用链的下一层，
   写出缺失的问题。不要为了凑“仔细”扫描整个工作区或重新下载已有竞品源码。
4. 将任务拆到一个主要行为、一组相邻文件、一个可验收交付；高风险核心文件串行修改。
5. 默认一个便宜执行模型处理一张卡；主模型只负责跨模块契约/安全取舍/最终审阅。
   子模型由用户或可用工具实际选择，不宣称自己设置了工具不支持的 DeepSeek 型号。
6. 一次失败先看一段明确日志和对应 XML/原始 run，再做局部修正；同一问题两轮无进展
   则保留最小复现交给审阅者，不靠无穷重试扩大上下文。
7. 定向回归过后，只有跨模块变化或阶段门禁才跑全套；文档修订不重复消耗公网/24h 长跑。

## 3. 推荐领取批次

| 批次 | 领取内容 | 交付后进入下一批的条件 |
| --- | --- | --- |
| 0 | P00 + P00c | 基线/竞品版本冻结；台账分片、租约和写入所有权可用 |
| 1a | P01 + P01b 最小切片 | 非周期语料 + curl/已发布版/候选/aria2 同条件可重跑；8 GiB 门禁生效 |
| 1b | P02 + P02a + Q00 | 参数/接口/CLI 全清单；no-op 白名单与消费地图可用；测试假覆盖已清理 |
| 2 | C01 -> C02 | HTTP 与断点已发布修复复核，加真实进程重启和公网断点证据 |
| 3 | C03 -> C04 | 来源身份、头隔离、刷新、状态和命令异步契约闭合 |
| 4 | C05 -> C06/C06b -> C07/C07a -> C08 | 本地模型与公网性能/资源/传输门槛通过；插件后端受同一预算；错误/重试可预测 |
| 5 | E01 | 生命周期/预算/取消/能力/JS ABI 可用，为协议插件提供稳定底座 |
| 6 | E00b -> E02-0 -> E02-HLS/E02-DASH/E03/E04b/E04/E05 | 哈希/媒体/服务运行时先冻结；各协议独立落地，不能只做注册占位 |
| 7 | O01 + O01b + A00 + A01 | CLI/插件/批量和 Android 真机实际消费同一 SDK，后台、保存和升级有证据 |
| 8 | A02 | 现有 UI 小缺陷修复、统一 Material 3、截图/交互/无障碍验收 |
| 9 | Q01 -> Q02 -> R01 | 最终候选长跑、公网全矩阵、完整打包与明确发布授权 |

1a/1b 可由两个执行者并行，但 P02 若修改公开类型须先停下让契约负责人审阅。
批次 4 以后仍复跑受影响的断点和真实链路，不是验证一次就永久通过。
E02 内部分成：现有 HLS VOD -> fMP4/init -> master/多轨 -> live -> DASH。
E03 分成 FTP/FTPS 与 SFTP；E05 分成 Metalink 与 ed2k。每个子项保留独立状态。
台账按 `ledger/<task-id>.csv` 分片，不能多人同时改一个总 CSV；领取时同时登记租约与写入路径。

## 4. 可直接复制给较弱模型的任务提示

```text
执行 TurboDL 工业级路线图中的【任务ID和一个具体子项】，不要重做全仓分析。
工作区 C:\Users\38476\Desktop\yunluo，PowerShell；TurboDL 与 YunGet 是独立仓库。
先读 TurboDL/engineering/industrial/HANDOFF.md 第1–2节、ROADMAP.md 对应任务卡，
然后只读以下入口：【由分配者填卡片列出的2–5个路径】。

依赖任务：【ID及其证据路径】。
允许写入：【明确路径集合】；其他执行者正在修改：【路径集合】。
本次目标行为：【具体触发、现有/预期行为和交付】。
已有相关测试/命令：【卡片入口，不是声称测试已经满足目标】。
必须满足：【卡片完成条件和NETWORK_ACCEPTANCE的场景ID】。
公网预算：【无 / EXECUTION_BOARD 账本中的 reserved_bytes 和 run_id】。

先确认 git status/HEAD，不覆盖用户改动；形成最小复现/消费点证据后再改。
不通过关闭自适应、忽略摘要、吞掉异常、跳过测试或放宽断言让结果变绿。
如果契约必须改变，先提交设计差异和兼容方案给负责人，不自行扩大为重写全部模块。
完成后给：更改文件、根因、回归和原始证据、未验证项、下一张可领取任务。
只更新自己负责的台账行。未具备网络或真机条件则写 BLOCKED，不写已通过。
不创建 Release、不覆盖旧包、不推线上；除非当前轮明确授权。
```

若任务只是清点/实验台建设，把“形成复现后再改”解释为建立记录工具，不无依据修改产品算法。
上游研究每次带着一个已复现差距读取相应实现并记录 commit/路径/原理/适用边界；
不得把“参考了 aria2”当作已完成改进，也不能只翻 README 后写“全面对齐”。

## 5. 首张任务的具体交付（P00）

在忽略的 `_bench/results/industrial/<run-id>/` 保存：

```text
baseline.json              # 两项目提交、版本、构建和二进制哈希、环境
competitors.json           # 各竞品准确版本/特性/命令/来源与许可证
ledger/<task-id>.csv        # 按任务分片的冻结台账；由聚合器生成只读汇总
leases/<task-id>.json       # owner、worktree、允许写路径、开始 HEAD、锁定文件
sources.private.json       # 本机保留；仅有授权来源，含秘密时严格不提交
```

在 `engineering/industrial/evidence/` 只存脱敏摘要/小型失败复现与原始证据的哈希引用。
大文件、下载内容、账号、完整 signed URL、Cookie、私有任务库均不提交。
基准字段至少按 NETWORK_ACCEPTANCE 第 2 节；脚本/数据源适配器放 `_bench/`，
不要把原始数据嵌进 README 让后续每个模型都读数千行日志。

## 6. 每张任务卡的交付格式

```text
Task: C02/R03
Status: VERIFYING (允许 TODO/IMPLEMENTING/VERIFYING/PASS/FAIL/BLOCKED)
Base: TurboDL commit / YunGet commit / binary SHA256
Changed: 文件列表 + 简短行为变化
Root cause or hypothesis: 已证实根因与未证实推断分开
Contract delta: 公共接口/默认值/格式变化；无则写无
Checks: 命令、退出码、实际执行数、摘要、原始run_id
Network/device: 来源类别、直连/代理、设备；没测则写未测
Evidence: 报告路径、输入/输出摘要、相关提交
Risks/blocker: 具体条件 + 继续所需的最小信息
Next: 已解锁任务ID；仍不能跨过的门禁
```

“测试通过”必须注明实际执行而非全 return；“更快”必须注明对谁、哪个场景、重复次数和误差。
遇到新隐性缺陷：立即给独立缺陷 ID、最小复现与影响边界，链接回所属任务；
数据损坏/凭据泄漏先暂停依赖链修复，其他小问题放台账，避免半路无边界换任务。

## 7. 审阅者只核对这些关键问题

- 有没有改偏 SDK/宿主边界、关闭重要策略、破坏旧字节码或发布格式？
- 证据是否证明真实行为：完整摘要、真实网络字节、实际 socket、独立进程断点、设备状态？
- 性能是不是同文件、同出口、同缓存和公平配置？有没有只删掉失败/变慢的样本？
- 有没有把未知判成功、把临时故障判数据无效，或者任务停止后仍有线程/写盘残留？
- 对协议/媒体不支持项是否明确拒绝、仍留在全范围台账，而不是把需求删掉？
- 核心阶段完成时重跑受影响的消费者；APP/UI 保留现有功能，Windows 范围没有被偷偷恢复。

本轮规划的完成条件是四份文档可互相定位、任务有真实源码入口和验收方法、
后续模型可按卡片执行。引擎工业级目标的完成条件仍是 ROADMAP 第 3 节全部通过。
