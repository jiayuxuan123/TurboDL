# Rebuild targets and release decisions

The native rebuild must first outperform the frozen 0.5.0.6 JVM SDK in each
applicable workload, then meet the frozen mature-engine reference gates. A
language change, increased test count, or one faster workload is not acceptance.

## Required gates

1. Correctness: complete independent hashes, recovery after cancellation and
   process death, credential isolation, source changes and valid media output.
   Existing protocol and plugin behavior cannot disappear during migration.
2. Performance: paired elapsed-time ratio confidence upper bound below 1.00
   against the old SDK in each supported case. Retain the mature reference
   upper bound of 1.10. Run defaults and common supported ceilings separately.
3. Resources: no confirmed CPU/RSS regression against the stable SDK; satisfy
   the applicable reference budget. Measure standalone engine processes, not
   the Python controller's RSS. Missing metrics remain unverified.
4. Coverage: cold/warm, small/large files, slow-tail, connection limits,
   adverse links, mirrors, media and mixed-protocol workloads. Development
   and held-out samples stay separate. Preserve unsuccessful observations.
5. Delivery: all mandatory protocol/platform/app gates and comparison evidence
   before switching the production default and publishing both projects.

## Current work order

- Diagnose the existing single-stream, latency, rate-limited and slow-tail
  regressions using phase timing and fair metadata/hash configuration.
- Fix the streaming/scheduler/storage path and recheck recovery invariants.
- Complete missing local comparison adapters and independent held-out cases.
- Complete ED2K, remaining network/storage faults and platform/host integration.
- Run sanitizer/fuzz/soak gates, integrate YunGet and replace analytics storage
  during the app phase, then complete final device/network acceptance.

## Evidence boundaries

The first nine-pair comparison failed the performance target. It also mixed
known-size SDK submission with unknown-size native submission, passed an
expected digest only to native, ran aria2 cold versus persistent hosts, and
measured native resources inside the Python process. Its raw observations stay
preserved as diagnostic evidence; they cannot authorize a parity claim.

Caching the Windows digest provider did not remove the measured gap in the
following smoke run. The earlier attribution to provider creation is not a
confirmed root cause. Continue from measurements instead of assuming it fixed.

Public-network testing is deferred by the user. Android and Apple devices are
unavailable. These gates stay open; local fixtures cannot complete them.
